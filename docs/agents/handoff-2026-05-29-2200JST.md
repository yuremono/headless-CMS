## 2. ローカル開発クイックスタート

### 前提

- Node.js + npm
- PostgreSQL（開発: ローカル `localhost:5432/headless_cms`。Supabase は未接続）
- ポート: **3000** = CMS、**3001** = Preview デモ（静的 HTML）

### 初回 / DB セットアップ

```bash
cp .env.example .env
# DATABASE_URL を環境に合わせて編集

brew services start postgresql@17   # または既存 Postgres
npx prisma generate
npx prisma migrate deploy          # init + audit_logs
npx tsx prisma/seed.ts
```

### 日常

```bash
# ターミナル 1 — CMS（1 プロセスのみ）
npm run dev                        # http://localhost:3000

# ターミナル 2 — Preview デモ
cd examples/preview && python3 -m http.server 3001

npm test
npm run test:coverage
npm run build                      # dev 停止後に単独実行
```

### 管理画面

| ページ | URL |
|--------|-----|
| ログイン | http://localhost:3000/login |
| ダッシュボード | http://localhost:3000/ |
| サイト概要 | http://localhost:3000/sites/main-site |
| コンテンツ種類 | http://localhost:3000/sites/main-site/content-types |
| メディア | http://localhost:3000/sites/main-site/media |

**ログイン（デモ）**: `admin@example.com` / `admin1234`（`ADMIN_DEMO_EMAIL` / `ADMIN_DEMO_PASSWORD` で上書き可）

## 4. アーキテクチャメモ

### データ取得（管理画面）

- **RSC**: `lib/admin/loader.ts` → `lib/db/*`（HTTP 経由しない）
- **Client**: `adminFetch` + `x-session-token` / cookie
- **分離**: 型 `admin-data-types.ts`、client 共通 utils `admin-data-utils.ts`、`AdminData.ts` / `loader.ts` は `server-only`

### 主要 lib 構成

```
lib/
├── admin/loader.ts
├── audit/log.ts              # 操作ログ記録
├── auth/
│   ├── roles.ts              # 4 ロール permission マトリクス
│   ├── site-role.ts          # site_members 解決
│   ├── production-config.ts  # CMS_AUTH_PROVIDER 等（骨格）
│   └── session-bridge.ts     # 本番セッション（スタブ）
├── content/
│   ├── store.ts, service.ts
│   └── section-patch.ts      # Phase 4 セクション PATCH
├── db/                       # sites, members, api-keys, audit-logs, site-export, create-site
├── preview/                  # 署名 previewToken 含む
├── sanitize/
├── schemas/
└── storage/                  # local（R2 は stub）
```

### Middleware（`middleware.mjs`）

| 役割 | 条件 |
|------|------|
| CORS | `/api/*`（`FRONTEND_BASE_URL` 既定 `http://localhost:3001`） |
| 管理 UI ガード | `CMS_ENFORCE_ADMIN_LOGIN=true` かつ `cms_session` 無し → `/login?redirect=` |

### Phase 3 権限

- 既定: **全操作許可**（デモ互換）
- `PHASE3_ENFORCE_ROLES=true`: 管理 API 全 route に permission 適用（`docs/agents/phase3-roles.md`）
- viewer UI: `AdminAccessContext` で編集ボタン非表示（enforce 時）

## 5. 特記事項・既知の問題

1. **`next dev` / `next build` は 1 プロセスのみ** — 並列起動で Turbopack SST / `.next/lock` エラー。修復: `pkill -f next; rm -rf .next`

4. **Prisma CLI** — `prisma.config.ts` で `import "dotenv/config"`（`npx prisma migrate deploy` がそのまま動く）

## 8. 主要 API エンドポイント

### 配信

- `GET /api/sites/{siteId}/content/{contentType}` — `Cache-Control: public, max-age=30, s-maxage=120`
- `GET /api/sites/{siteId}/content/{contentType}/{id}` — `max-age=60, s-maxage=300`
- プレビュー: `?draft=true&previewToken=` — `no-store`

### 管理（追加分を含む）

| メソッド | パス | 備考 |
|---------|------|------|
| GET/POST | `/api/admin/sites` | 一覧 / サイト作成 |
| GET/POST | `.../members` | メンバー一覧 / 招待 |
| PATCH/DELETE | `.../members/{memberId}` | ロール変更 / 削除 |
| POST | `.../api-keys/rotate` | API キー再発行（平文はレスポンスのみ） |
| GET | `.../audit-logs` | 操作ログ（owner/admin） |
| GET | `.../export` | サイト JSON エクスポート |
| PATCH | `.../content/{type}/{id}/sections/{sectionId}` | セクション部分更新（Phase 4） |

従来の content CRUD / publish / unpublish / duplicate / assets は [architecture.md](./architecture.md) 参照。
