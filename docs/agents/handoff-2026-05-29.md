## 2. ローカル開発クイックスタート

### 前提

- Node.js + npm
- PostgreSQL（開発環境では Homebrew `postgresql@17` で起動実績あり）
- ポート: **3000** = CMS、`3001` = Preview デモ（Next ではない）

### 初回 / DB セットアップ

```bash
cp .env.example .env
# DATABASE_URL を環境に合わせて編集

brew services start postgresql@17   # または既存 Postgres
npx prisma generate
npx prisma migrate deploy          # 初回 migration: 20260529120000_init
npx tsx prisma/seed.ts             # npm run prisma:seed は rtk 環境で失敗する場合あり
```

### 日常

```bash
# ターミナル 1 — CMS（1 プロセスのみ。複数起動すると Next.js 16 がロックエラー）
npm run dev                        # http://localhost:3000

# ターミナル 2 — Preview デモ
cd examples/preview && python3 -m http.server 3001

npm run build
npm test
npm run test:coverage              # lib/** + app/api/** スコープ（約 88%）
```

### 管理画面

| ページ | URL |
|--------|-----|
| ログイン | http://localhost:3000/login |
| ダッシュボード | http://localhost:3000/ |
| サイト概要 | http://localhost:3000/sites/main-site |
| コンテンツ種類 | http://localhost:3000/sites/main-site/content-types |
| メディア | http://localhost:3000/sites/main-site/media |

**ログイン（デモ）**: `admin@example.com` / `admin1234`（`ADMIN_DEMO_EMAIL` / `ADMIN_DEMO_PASSWORD` で上書き可）

## 4. アーキテクチャメモ（実装と docs の差分）

### データ取得（管理画面 RSC）

Server Component は **HTTP fetch せず** `lib/admin/loader.ts` → `lib/db/*` を直接呼び出し（401 回避）。

Client Component（ContentForm / ContentList）は `adminFetch` + `x-session-token`。

Server 専用データ層: `components/admin/AdminData.ts` + `lib/admin/loader.ts` は `import 'server-only'`。型は `admin-data-types.ts`、クライアント共有可能なユーティリティは `admin-data-utils.ts` に分離。

### 主要 lib 構成（実装済み）

```
lib/
├── admin/loader.ts      # RSC 用 DB ローダー
├── auth/                # API キー・セッション・プレビュートークン
├── content/             # store, service, mappers, types
├── db/                  # prisma, sites, assets, site-resolver
├── http.ts
├── preview/             # build-preview-url, get-preview-token
├── sanitize/            # richText HTML サニタイズ
├── schemas/             # content-types JSON 読込・検証
└── storage/             # local upload（R2 は stub）
```

**未作成**: `lib/sections/`（`docs/agents/project.md` に記載あるが未実装。セクション定義は content-types JSON + SectionEditor 側）

### Middleware

- ファイル: **`middleware.mjs`**（`.ts` は ESM/CJS 競合のため `.mjs` に変更）
- 役割: `/api/*` 向け CORS（`FRONTEND_BASE_URL` 既定 `http://localhost:3001`）
- Next.js 16 では middleware 非推奨 → 将来 proxy 移行を検討

### 設定ファイル

| `tailwind.config.cjs` | MC/BC/TC 等を `scss/_01variables.scss` 変数にマッピング |

## 5. 特記事項・既知の問題

### 運用上の注意

1. **`next dev` / `next build` は 1 プロセスのみ** — 複数サブエージェント / ターミナルから同時起動すると「Another next dev/build process is already running」で失敗する。確認前に `lsof -ti:3000 | xargs kill` 等で整理。
2. **Preview は :3001、CMS は :3000** — ポートを取り合わないこと。
3. **seed 再実行** — `npx tsx prisma/seed.ts` を推奨（`npm run prisma:seed` が rtk ラッパーで失敗する環境あり）。再 seed 後は `examples/preview/js/config.js` の `contentId` を更新すること。
4. **siteId** — Admin URL は slug `main-site` で問題なし。Preview / curl では UUID または slug を API が解決。
5. **Prisma / dotenv** — `prisma.config.ts` は先頭で `import "dotenv/config"` を読み込む。CLI（`migrate` / `db seed`）実行時も `.env` の `DATABASE_URL` が必要。Supabase 接続時は Direct（5432）で migrate/seed、Pooler（6543）はアプリ runtime 用（`.env.example` 参照）。

### 解消済み（本セッション後半）

## 8. 主要 API エンドポイント（実装済み）

### 配信

- `GET /api/sites/{siteId}/content/{contentType}`
- `GET /api/sites/{siteId}/content/{contentType}/{id}`
- プレビュー: `?draft=true&previewToken=xxxx`

### 管理

- `GET /api/admin/sites`
- `POST /api/admin/sites` — サイト新規作成（`content-types` 取り込み + API キー発行。平文キーはレスポンスのみ）
- `GET /api/admin/dashboard`
- `GET /api/admin/sites/{siteId}` → `{ schemas }`
- `GET /api/admin/sites/{siteId}/schemas`
- `GET /api/admin/sites/{siteId}/content-types`
- `GET|POST /api/admin/sites/{siteId}/content/{contentType}`
- `GET|PATCH|DELETE /api/admin/sites/{siteId}/content/{contentType}/{id}`
- `POST .../publish` / `.../unpublish` / `.../duplicate`
- `GET|POST /api/admin/sites/{siteId}/assets`
