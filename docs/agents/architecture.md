# アーキテクチャ

この CMS はヘッドレス構成です。CMS 側はコンテンツを HTML として描画せず、管理画面・管理 API・JSON 配信 API を提供する。案件フロントは別リポジトリで API を取得して表示する。

## 境界

| 領域 | CMS の責務 | フロントの責務 |
| --- | --- | --- |
| コンテンツ | 作成・編集・公開状態管理 | 取得して表示 |
| スキーマ | DB と Admin API の整合性 | 必要な型への変換 |
| 表示 | 管理画面のみ | サイト UI・CSS・アニメーション |
| デプロイ | CMS として独立 | 案件ごとに独立 |

CMS 側に案件フロント固有の表示ロジックや CSS を混ぜない。

## データモデル

- `Site`: 現在は単一運用だが、API / DB 互換のため残っている。
- `ContentModel`: コンテンツ種類とフィールド定義。
- `Content`: 本文、SEO、公開状態。
- `Asset`: アップロード画像。
- `AuditLog`: 管理操作ログ。

UI ではサイト切り替えを扱わない。API や CLI に残る `siteId` は後方互換の実装詳細として扱う。

## 配信

配信 API は公開済みコンテンツのみ返す。公開・非公開・更新時は配信用タグを失効し、フロント側が再取得できる状態にする。

プレビュー URL は `FRONTEND_BASE_URL` を起点に生成する。表示フロントは別リポジトリで実装する。

## セキュリティ

- 管理操作は認証と権限チェックを通す。
- Admin API は管理 API キーまたは管理セッションを要求する。
- richText は保存前にサニタイズする。
- DB 直書き、raw SQL、seed 再投入、`migrate reset` は通常運用で禁止する。
- 秘密情報はリポジトリに書かない。

## 実装方針

- Route Handler は薄く保ち、処理は `lib/` に寄せる。
- Prisma は `lib/db/` 経由で扱う。
- 管理 UI は `components/admin/` に閉じる。
- CLI / MCP は Admin API 経由で CMS を操作する。
